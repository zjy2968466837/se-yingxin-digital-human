# 功能清单与分解 —— 大学生迎新导引服务数字人系统

> 版本：v1.0 ｜ 依据：[需求规格说明书](需求规格说明书.md) v1.0、[项目计划](项目计划.md)、仓库现有微服务与前端结构
> 用途：功能拆分基线。每个功能项分配唯一 ID，可直接用于 Issue 拆分、WBS、测试用例编号与进度跟踪。
> 各功能的技术风险与降级方案见 [技术难点分析](技术难点分析.md)。

## 0. 阅读说明

### 0.1 优先级

| 级别 | 含义 | 对应里程碑 |
|------|------|-----------|
| **P0** | 核心链路，缺其则系统不可演示 | M4 |
| **P1** | 主要功能，构成完整业务闭环 | M5 |
| **P2** | 增强/加分项，可降级或后置 | M5–M6 |

### 0.2 实现状态

| 状态 | 含义 |
|------|------|
| ✅ 已实现 | 代码已具备 |
| 🟡 骨架 | 仅有工程骨架/静态页面/连通性自检（`PingController`） |
| ⬜ 待开发 | 尚未开始 |

> 当前仓库整体处于 **M3 骨架**：网关路由与 9 个服务可启动、`/api/<服务>/ping` 自检通过；前端管理后台仅有登录/概览/问答库三个静态页，小程序仅有首页/我的两页。故除基础设施外的业务功能均为 **⬜ 待开发**。

### 0.3 角色

| 角色 | 说明 | 主要使用端 |
|------|------|-----------|
| 新生 | 系统第一用户，报到全流程 | 微信小程序 / H5 |
| 家长 / 访客 | 只读咨询，不涉及个人数据 | 小程序 / 官网嵌入 |
| 现场志愿者 / 辅导员 | 迎新现场答疑与处理异常 | PC 大屏 / 后台 |
| 学校管理员 | 学工、后勤、保卫、学院分权维护内容 | 管理后台 |
| 系统运维 | 部署、监控、配置 | 运维后台 |

## 7. 数据与接口约定（摘要）

- **数据库**：统一 `yingxin` 库，按服务分表；Redis 缓存热点问答与令牌
- **接口风格**：RESTful，统一前缀 `/api/<服务简称>/**`；实时交互走 WebSocket
- **统一响应体**：`{ code, message, data }`，错误码分段（1xxx 认证 / 2xxx 业务 / 9xxx 系统）
- **鉴权**：`Authorization: Bearer <jwt>`，网关统一校验，白名单放行 ping/login
- **文档**：每服务 springdoc，`/swagger-ui.html`
