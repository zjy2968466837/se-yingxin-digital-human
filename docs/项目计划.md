# 项目计划 —— 迎新数字人系统（草案）

## 里程碑

| 阶段 | 产出 | 截止日期 |
|------|------|----------|
| M1 立项 | 选题确定、需求规格说明书 v1.0、技术选型决议 | 待定 |
| M2 设计 | 架构设计（微服务拆分）、接口约定、UI 原型、WBS | 待定 |
| M3 骨架 | 仓库骨架跑通：Docker 基础设施 + 网关 + 一个示例服务 + 小程序/后台空页面联通 | 待定 |
| M4 核心迭代 | 智能问答 + 报到导引（核心链路）可演示 | 待定 |
| M5 扩展迭代 | 导航、资助、生活服务、安全教育、管理后台 | 待定 |
| M6 数字人集成 | 数字人形象、语音、实时流接入主界面 | 待定 |
| M7 测试交付 | 系统测试报告、演示视频、答辩材料 | 待定 |

## 建议分工方向

| 方向 | 内容 |
|------|------|
| 后端 A | 网关、认证、报到导引服务 |
| 后端 B | 问答服务（问答库+意图）、内容服务 |
| 前端 A | uniapp 小程序主交互界面 |
| 前端 B | Vue3 管理后台 |
| 数字人/算法 | 形象渲染、语音 ASR/TTS、LLM 接入 |
| 数据/运维 | 数据库设计、Docker 部署、地图数据整理 |

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 数字人 SDK/流媒体方案复杂度高 | 高 | 高 | M3 前先做 2D 降级方案；3D 作为加分项 |
| 微信接口需企业资质（人脸核身等） | 高 | 中 | 课程演示用模拟核验，文档说明生产对接方式 |
| LLM API 成本/网络 | 中 | 中 | 问答库优先命中，LLM 仅兜底 |
| 学校数据（地图、报到流程）缺失 | 高 | 中 | 用虚构校园数据 + 可配置化 |
| 成员进度不同步 | 高 | 中 | 每周例会 + Issue 跟踪 + dev 分支集成 |
