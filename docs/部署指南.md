# 部署指南（本地开发 → 云部署 Azure）

## 环境分层

同一套代码，三处配置不同，**代码零改动**，只切配置/环境变量：

| 环境 | 数据库 | Redis | 配置方式 |
|------|--------|-------|----------|
| 本地开发 | Azure Database for MySQL 开发库（脱敏副本） | 本机 Docker Redis 7 | `application-dev.yml` + `.env` |
| 云上部署 | Azure Database for MySQL（PaaS） | 云服务器上的 Redis 7（systemd 系统服务） | `application-prod.yml` / 环境变量 |
| 演示/联调 | 同上（云） | 同上（云） | 同 prod |

> 本项目实际基础设施（2026-09 实测确认）：
> - MySQL：Azure PaaS 弹性服务器 `yingxin-mysql-ea`（强制 SSL，库 `yingxin`）
> - Redis：Azure Linux VM 上的系统服务（非容器），端口 6379
> - 云服务器：一台 Azure Linux VM（也是后端微服务所在机器）

---

## 本地：启动基础设施（仅 Redis）

```bash
cd backend
docker compose up -d
```

- Redis：`127.0.0.1:6379`（仅本机）

验证：`docker compose ps` 中 redis 容器 healthy。

启动微服务与前端见《环境搭建指南.md》，开发环境应加载 `.env` 并连接 Azure 开发库（脱敏副本）。

## 云上：Azure 部署

### 1. 基础设施概览（已就绪）

| 资源 | 位置 | 连接信息 |
|------|------|----------|
| MySQL（PaaS） | `yingxin-mysql-ea`（East Asia） | `yingxin-mysql-ea.mysql.database.azure.com:3306`，库 `yingxin`，强制 SSL |
| Redis | Azure Linux VM，systemd 服务 | `127.0.0.1:6379`（后端与 Redis 同机，走内网） |
| 后端微服务 | Azure Linux VM（Docker 或裸 `java -jar`） | 连 `127.0.0.1:6379` + MySQL 公网地址 |

安全约束（务必遵守）：
- **MySQL PaaS 防火墙**只放行需要访问的 IP：本地开发机、云服务器出口 IP。不要 `0.0.0.0/0` 全放。
- **VM 的 6379 只对 VM 内部/后端开放**，不要对公网开放；后端连 `127.0.0.1:6379`。
- MySQL PaaS 强制 SSL，JDBC 连接串必须带 `useSSL=true&requireSSL=true`。

### 2. 准备环境变量文件（严禁提交 git）

先复制模板：

```bash
cd backend
cp .env.example .env       # 本地开发
cp .env.example .env.prod  # 云上生产（在 VM 上执行）
```

在**云服务器**上创建 `backend/.env.prod`（`.gitignore` 已排除 `*.env*`）：

```ini
MYSQL_HOST=yingxin-mysql-ea.mysql.database.azure.com
MYSQL_PORT=3306
MYSQL_DB=yingxin
MYSQL_USER=azure
MYSQL_PASSWORD=<PaaS 上 azure 用户的密码>
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<VM 上 Redis 的 requirepass>
```

### 3. `application-dev.yml` / `application-prod.yml` 模板（可基于仓库示例）

仓库提供：

- `backend/application-dev.example.yml`
- `backend/application-prod.example.yml`

复制后作为实际运行文件（不提交 Git）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST}:${MYSQL_PORT}/${MYSQL_DB}?useSSL=true&requireSSL=true&useUnicode=true&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai
    username: ${MYSQL_USER}
    password: ${MYSQL_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      port: ${REDIS_PORT}
      password: ${REDIS_PASSWORD}
```

> 模板里的密码全部来自环境变量，不写死。

### 4. 初始化数据库结构

PaaS 的 MySQL 表结构与本地一致，但**不会自动执行** `init-sql/`（那是 Docker 镜像的初始化钩子）。上云时要手动导入：

```bash
# 从本地或云服务器（装了 mysql client）执行：
mysql -h $MYSQL_HOST -u $MYSQL_USER -p$MYSQL_PASSWORD --ssl-mode=REQUIRED $MYSQL_DB < backend/init-sql/01-init.sql
```

当前 `init-sql/01-init.sql` 只建库；各业务表由服务启动时的迁移（jpa/springdoc 或手动 DDL）生成。团队补充建表脚本后，把新 SQL 追加进 `init-sql/` 并按需执行。

### 5. 确认云服务器 → MySQL 已放行（关键前提）

MySQL PaaS 防火墙需包含**云服务器的公网出口 IP**。若后端部署在与 Redis 同一台 VM，其出口 IP 必须已加进 PaaS 防火墙规则，否则所有 SQL 请求超时。检查/添加：

```bash
# 查看当前规则
az mysql flexible-server firewall-rule list -g <资源组> -n <服务器名> -o table

# 添加云服务器出口 IP
az mysql flexible-server firewall-rule create -g <资源组> -n <服务器名> \
  -r allow-azure-vm --start-ip-address <VM出口IP> --end-ip-address <VM出口IP>
```

> 命令行如果报 `InternalServerError`，可改用 ARM API：
> ```bash
> SUB=$(az account show --query id -o tsv)
> az rest --method put --url "https://management.azure.com/subscriptions/$SUB/resourceGroups/<资源组>/providers/Microsoft.DBforMySQL/flexibleServers/<服务器名>/firewallRules/allow-azure-vm?api-version=2023-12-30" \
>   --body '{"properties":{"startIpAddress":"<VM出口IP>","endIpAddress":"<VM出口IP>"}}'
> ```

### 6. 后端微服务上云（推荐 `systemd + jar`）

```bash
# 云服务器上，每进到 services/<服务> 打包（或 CI 里打包后上传）
mvn clean package -DskipTests

# 用 prod profile + 环境变量启动
cp backend/.env.prod /etc/yingxin.env
java -jar gateway.jar --spring.profiles.active=prod $(cat /etc/yingxin.env | sed 's/^/--/; s/^--\([^=]*\)=/--\1=/' | tr '\n' ' ')
```

> 可选容器化仅限 SpringBoot 应用层；MySQL/Redis 生产环境不容器化。

### 7. 前端静态部署（可选）

- 管理后台构建后放 Nginx：`frontend/admin-web` `pnpm build` → 产物到 VM 的 Nginx root
- 小程序走微信开发者工具上传，或云托管

## 检查清单（云上）

- [ ] `.env` / `.env.prod` / `application-*.yml` 未提交 git（仅 `.example` 入库）
- [ ] MySQL PaaS 防火墙只放行本地 + 云服务器出口 IP，未全放 `0.0.0.0/0`
- [ ] `application-prod.yml` JDBC 带 `useSSL=true&requireSSL=true`
- [ ] VM 的 6379 未对公网开放
- [ ] 后端以 `prod` profile 启动，`/actuator/health` 返回 UP
- [ ] 云服务器 → MySQL 实测可连通（见第 6 步前置）

## 演示期建议

- 课程演示「一台云 + 云数据库」即可：MySQL 用 PaaS（自动备份免运维）、Redis 用 VM 系统服务、后端跑 VM

- 定期备份：PaaS 自带自动备份；Redis 数据用 `SAVE` 或 RDB 快照
