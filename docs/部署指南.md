# 部署指南（本地开发 → 云部署 Azure）

## 环境分层

同一套代码，三处配置不同，**代码零改动**，只切配置/环境变量：

| 环境 | 数据库 | Redis | 配置方式 |
|------|--------|-------|----------|
| 本地开发 | 本机 Docker MySQL 8（`docker-compose.yml`） | 本机 Docker Redis 7 | `application.yml` 默认值，连 `localhost` |
| 云上部署 | Azure Database for MySQL（PaaS） | 云服务器上的 Redis 7（systemd 系统服务） | `application-prod.yml` / 环境变量 |
| 演示/联调 | 同上（云） | 同上（云） | 同 prod |

> 本项目实际基础设施（2026-09 实测确认）：
> - MySQL：Azure PaaS 弹性服务器 `yingxin-mysql-ea`（强制 SSL，库 `yingxin`）
> - Redis：Azure Linux VM 上的系统服务（非容器），端口 6379
> - 云服务器：一台 Azure Linux VM（也是后端微服务所在机器）

## 本地：启动基础设施（MySQL + Redis）

```bash
cd backend
docker compose up -d
```

- MySQL：`localhost:3306`，库 `yingxin`，用户 `yingxin/yingxin123`（仅本地，见 `docker-compose.yml`）
- Redis：`localhost:6379`，无密码（仅本地）

验证：`docker compose ps` 两个容器 healthy。

> Docker 的安装（WSL 原生 Engine / Windows Docker Desktop）与**国内镜像加速配置**见
> 《环境搭建指南.md》——不配加速器时这一步会一直卡在拉镜像。

启动微服务与前端见《环境搭建指南.md》，本地连 `application.yml` 预设的 `localhost` 即可，无需改代码。

## 云上：Azure 部署

### 1. 基础设施概览（已就绪）

| 资源 | 位置 | 连接信息 |
|------|------|----------|
| MySQL（PaaS） | `yingxin-mysql-ea`（East Asia） | `yingxin-mysql-ea.mysql.database.azure.com:3306`，库 `yingxin`，强制 SSL |
| Redis | Azure Linux VM，systemd 服务 | `127.0.0.1:6379`（后端与 Redis 同机，走内网） |
| 后端微服务 | Azure Linux VM（Docker 或裸 `java -jar`） | 连 `127.0.0.1:6379` + MySQL 公网地址 |

安全约束（务必遵守）：
- **MySQL PaaS 防火墙**只放行需要访问的 IP：本地开发机、云服务器出口 IP。不要 `0.0.0.0/0` 全放。
- **VM 的 6379 只对 VM 内部/后端开放**，不要对公网开放；后端连 `127.0.0.1:6379`。
- MySQL PaaS 强制 SSL，后端需设 `MYSQL_SSL_MODE=REQUIRED`（脚手架 `application.yml` 已内置该变量，默认 `PREFERRED` 供本地使用）

### 2. 准备环境变量文件（严禁提交 git）

在**云服务器**上创建 `backend/.env.prod`（`.gitignore` 已排除 `*.env*`）：

```ini
# 该文件同时被 docker-compose.prod.yml（env_file）和裸 jar 启动方式读取
MYSQL_HOST=yingxin-mysql-ea.mysql.database.azure.com
MYSQL_PORT=3306
MYSQL_DB=yingxin
MYSQL_USER=azure
MYSQL_PASSWORD=<PaaS 上 azure 用户的密码>
MYSQL_SSL_MODE=REQUIRED
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<VM 上 Redis 的 requirepass>
# 可选：镜像 tag
IMAGE_TAG=latest
```

### 3. 配置方式：无需 `application-prod.yml`

脚手架的 `application.yml` 已把连接信息全部写成环境变量占位并带本地默认值，因此
**本地与云上共用同一份配置，只靠环境变量区分**，不需要额外写 `prod` profile 文件：

```yaml
# services/<服务>/src/main/resources/application.yml（已提交，不含任何密码）
url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:yingxin}?...&sslMode=${MYSQL_SSL_MODE:PREFERRED}
username: ${MYSQL_USER:yingxin}
password: ${MYSQL_PASSWORD:yingxin123}   # 默认值仅本地有意义
```

云上只要注入第 2 步的 `.env.prod` 即可。若个别服务确需额外覆盖，再另建
`application-prod.yml`（已在 `.gitignore` 中排除，不会误提交）。

以裸 jar 启动时把环境变量导出即可：

```bash
set -a && . backend/.env.prod && set +a
java -jar services/gateway/target/gateway-1.0.0-SNAPSHOT.jar
```

### 4. 初始化数据库结构

PaaS 的 MySQL 表结构与本地一致，但**不会自动执行** `init-sql/`（那是 Docker 镜像的初始化钩子）。上云时要手动导入：

```bash
# 从本地或云服务器（装了 mysql client）执行：
mysql -h $MYSQL_HOST -u $MYSQL_USER -p$MYSQL_PASSWORD --ssl-mode=REQUIRED $MYSQL_DB < backend/init-sql/01-init.sql
```

当前 `init-sql/01-init.sql` 只建库；各业务表由服务启动时的迁移（jpa/springdoc 或手动 DDL）生成。团队补充建表脚本后，把新 SQL 追加进 `init-sql/` 并按需执行。

### 5. 确认云服务器 → MySQL 已放行（关键前提）

MySQL PaaS 防火墙需包含**云服务器的公网出口 IP**。若后端部署在与 Redis 同一台 VM，其出口 IP 必须已加进 PaaS 防火墙规则，否则所有 SQL 请求超时。

> ✅ 本项目的这条规则已加好并实测通过（2026-09-09）：规则名 `allow-azure-vm`，放行云服务器出口 IP
> `52.184.100.132`，与既有的 `allow-home-net`（`182.150.101.0–255`，本地开发用）并存。
> 下列命令供核对或在换机器时新增：

```bash
# 查看当前规则
az mysql flexible-server firewall-rule list -g <资源组> -n <服务器名> -o table

# 添加云服务器出口 IP
az mysql flexible-server firewall-rule create -g <资源组> -n <服务器名> \
  -r allow-azure-vm --start-ip-address <VM出口IP> --end-ip-address <VM出口IP>
```

> 命令行如果报 `InternalServerError`，可改用 ARM API：
> ```bash
> SUB=$(az account show --query id -o tsv)
> az rest --method put --url "https://management.azure.com/subscriptions/$SUB/resourceGroups/<资源组>/providers/Microsoft.DBforMySQL/flexibleServers/<服务器名>/firewallRules/allow-azure-vm?api-version=2023-12-30" \
>   --body '{"properties":{"startIpAddress":"<VM出口IP>","endIpAddress":"<VM出口IP>"}}'
> ```

### 6. 后端微服务上云（Docker Compose）

每个服务都自带 `Dockerfile`（多阶段构建：容器内 Maven 打包 → JRE 运行），
所以**云服务器只需装 Docker，不需要装 Java/Maven**。

```bash
cd backend
# 首次或代码更新后：构建并启动（--build 会重新构建镜像）
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build

# 查看状态（9 个服务）
docker compose -f docker-compose.prod.yml ps

# 只看日志
docker compose -f docker-compose.prod.yml logs -f gateway
```

**内存吃紧时按需只起部分服务**（本机约 3.8G，9 个服务全开较紧张）：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d gateway auth-service qa-service
```

> 说明：`docker-compose.prod.yml` **只编排后端服务**，不再包含 MySQL/Redis 容器——
> MySQL 用 Azure PaaS、Redis 用 VM 上的 systemd 服务。服务内 `JAVA_OPTS` 默认
> `-Xmx256m`，如需调整可在 compose 里覆盖该环境变量。
>
> 若偏好不用容器，也可在 VM 上装 JDK 17 后以裸 jar 方式启动（见第 3 步的环境变量导出）。
