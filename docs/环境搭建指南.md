# 环境搭建指南

> 新成员按本文档从零搭建开发环境，遇到问题在群里提 Issue。

## 一、需要安装的基础软件

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | **17** | 后端 Spring Boot 3 必须（JDK 21 也能构建，但不要用 11） |
| Node.js | **22.22.1** | 前端（小程序 + 管理后台）；仓库已用 `.nvmrc` / `.node-version` 声明 |
| pnpm | **12** | 前端包管理器，`npm i -g pnpm@12`；版本过低会导致小程序依赖安装行为不一致 |
| Maven | **不用装** | 用仓库自带的 `./mvnw`，会自动下载固定版本 3.9.12 |
| Docker Compose | **v2** | 启动 MySQL + Redis（`docker compose` 子命令形式，非旧的 `docker-compose`） |
| 微信开发者工具 | 最新 | 小程序调试（Windows/Mac） |
| IDE | IntelliJ IDEA（后端）+ VS Code（前端） | IDEA 学生邮箱可免费申请教育许可 |

**WSL 还是 Windows 都可以**：两者均受支持，仓库已用 `.gitattributes` + `.editorconfig` 统一换行符与编码，
不会出现"Windows 成员提交 CRLF、Linux 成员看到全文件改动"的问题。选哪个看个人习惯，不必强求一致。

**一次性配置 Maven 镜像（强烈建议）**：国内直连 Maven 中央仓库很慢，复制仓库里的模板即可。

WSL / Linux / macOS：

```bash
mkdir -p ~/.m2 && cp docs/maven-settings.xml ~/.m2/settings.xml
```

Windows（在 WSL 之外用 IDEA 或命令行时）：把 `docs/maven-settings.xml` 复制到
`C:\Users\<你的用户名>\.m2\settings.xml`。

> 若你已有 `~/.m2/settings.xml`（例如配了公司私服），请手工把 `<mirror>` 段合并进去，不要直接覆盖。

> 完整版本清单，以及"改版本时该动哪个文件"，见 [开发环境版本.md](开发环境版本.md)。

## 二、启动基础设施（MySQL + Redis）

```bash
cd backend
docker compose up -d
```

启动后：

- MySQL：`localhost:3306`，库 `yingxin`，用户 `yingxin/yingxin123`（本地开发用，密码见 `docker-compose.yml`）
- Redis：`localhost:6379`，无密码（仅本地）

验证：`docker compose ps` 两个容器都是 healthy 即可。

> 不用 Docker 的话，本机直装 MySQL 8 与 Redis（Windows 可用 Memurai 或 WSL 内 Redis），建同名库与账号即可。

> ⚠️ 本地与云上 Redis 密码不同：**本地无密码**，**云上有密码**。服务的 `application.yml` 已把
> 连接信息写成环境变量占位（本地用默认值、云上用 `REDIS_PASSWORD` 等注入），**代码与配置文件零改动**，
> 具体见《部署指南.md》。

## 三、启动后端微服务

```bash
cd backend
./mvnw clean install -DskipTests              # 首次构建（自动下载 Maven 3.9.12）
./mvnw -pl services/gateway spring-boot:run   # 网关先起
./mvnw -pl services/auth-service spring-boot:run   # 再按需启动其他服务
```

> Windows CMD / PowerShell 下用 `mvnw.cmd` 代替 `./mvnw`（例如 `mvnw.cmd clean install -DskipTests`）。
> IntelliJ IDEA 里也可以直接把 Maven 指向 `backend/mvnw`，避免用到 IDE 自带的 Maven 版本。

- 网关统一入口：`http://localhost:8080`
- 各服务端口：网关 8080，auth 8100、qa 8101、checkin 8102、navigation 8103、aid 8104、life 8105、content 8106、admin 8107
- 网关路由：`/api/<服务简称>/**`（转发不裁剪前缀，直连与走网关路径一致），如 `/api/auth/**` → auth-service
- 连通性自检：`curl http://localhost:8080/api/auth/ping`（经网关）或 `curl http://localhost:8100/api/auth/ping`（直连）
- 接口文档（springdoc，直连各服务端口）：`http://localhost:8100/swagger-ui.html`

## 四、启动前端

两个前端项目相互独立，各自安装依赖（**注意二者 vite 版本不同**，见下方说明）。

```bash
# 管理后台（Vue3 + Vite 8 + Element Plus）
cd frontend/admin-web
pnpm install
pnpm dev        # http://localhost:5173，/api 已由 vite 代理到网关 8080

# 小程序（uni-app + Vue3，编译为微信小程序）
cd frontend/miniprogram
pnpm install
pnpm dev:mp-weixin
# 然后用微信开发者工具导入 dist/dev/mp-weixin 目录，填自己的测试 AppID
# 生产构建：pnpm build:mp-weixin → dist/build/mp-weixin
```

> ⚠️ 版本约束（已在 package.json 中钉死，不要随手升级）：
> - **小程序端 vite 必须是 5.2.8**：`@dcloudio/vite-plugin-uni` 的 peerDependencies 把它精确锁在
>   `5.2.8`，升级到 vite 6/7/8 会导致编译失败。
> - 管理后台用 vite 8，需要 Node ≥ 20。
> - uni-app 各包统一使用同批次版本号 `3.0.0-5020420260813001`，**不要混用不同批次**
>   （`latest` 标签指向的是 2021 年的陈旧 alpha，按 `latest` 装会出错）。
> - 小程序真机/工具调试连后端需在微信开发者工具中勾选「不校验合法域名」（开发期）。

## 七、常见问题

- **3306 端口被占**：本机装过 MySQL 的先停掉服务，或改 `docker-compose.yml` 端口映射
- **微信开发者工具连不上后端**：真机调试需 https 与合法域名，开发期在开发者工具里勾选「不校验合法域名」
- **Maven 下载慢**：`settings.xml` 配置阿里云镜像（见 backend/README.md）
- **pnpm/`pnpm: command not found`**：确认 Node ≥ 20；`npm i -g pnpm`，若仍找不到命令，把 npm 全局 bin 加进 PATH
  （`export PATH="$(npm config get prefix)/bin:$PATH"`，可写进 `~/.bashrc`）
- **`pnpm install` 提示 `Ignored build scripts` 并返回非 0 退出码**：pnpm 12 默认拦截依赖的构建脚本。
  小程序端已在 `pnpm-workspace.yaml` 里用 `allowBuilds` 显式批准 esbuild/core-js。注意 pnpm 12 **不再读取
  package.json 里的 `pnpm` 字段**，新增需构建的依赖时要在这个 yaml 里加。若只是被拦下，实际构建通常仍正常。
- **小程序编译报 vite 版本相关错误**：`@dcloudio/vite-plugin-uni` 要求 vite 精确为 `5.2.8`，
  不要跟随管理后台升到 vite 8，两个前端的 vite 版本本就不同。
- **网关路由不生效/404**：确认配置写在 `spring.cloud.gateway.server.webflux` 下
  （Spring Cloud Gateway 4.3+ 的新前缀），旧的 `spring.cloud.gateway.routes` 会被静默忽略。
- **想看接口文档**：springdoc 直连各服务端口，如 `http://localhost:8100/swagger-ui.html`
  （不是走网关 `/api/...` 前缀）。
- **`docker compose up` 报 `lower_case_table_names` 相关错误**：该参数只在数据卷首次初始化时生效，
  改过后需 `docker compose down -v` 删卷重建。
