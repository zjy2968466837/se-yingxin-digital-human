# 临时演示：页面 → 后端 → 云数据库

> 目标：在浏览器里点「新建会话」，数据真的写进腾讯云 CloudBase 的 MySQL，能当场查库核对。
> 全程走项目自己的技术栈：**Vue 3 + Element Plus → Vite 代理 → Spring Boot（qa-service）→ MyBatis-Plus → MySQL**。
> 只收窄了页面和功能（一个表、增 + 查 + 删），没有绕过后端。

## 0 涉及的文件

| 层 | 位置 | 说明 |
|---|---|---|
| 前端页面 | `frontend/admin-web/src/views/QaView.vue` | 表格 + 新建对话框 + 删除确认 + 响应包体回显 |
| 前端接口 | `frontend/admin-web/src/api/qa.js` | 走 `request.js`（axios，baseURL `/api`） |
| 控制器 | `backend/services/qa-service/.../controller/QaSessionController.java` | `POST / GET / GET{id} / DELETE` |
| 服务 | `.../service/QaSessionService.java` | 显式 `deleted = 0`、删除写行 id、分页 |
| 映射 | `.../mapper/QaSessionMapper.java` | `extends BaseMapper<QaSession>` |
| 实体 | `.../entity/QaSession.java` | `@TableId(ASSIGN_ID)` 雪花主键 + 审计字段自动填充 |

数据库：CloudBase MySQL（CynosDB 8.0），库名 = 环境 ID，表 `qa_session`。

| 步 | 操作 | 该说的 |

## 3 当场查库核对（不经过应用）

```powershell
mysql --host=<公网地址> --port=<端口> --user=<账号> -p --default-character-set=utf8mb4 -e "
SELECT id, user_id, channel, deleted, create_time
FROM \`student-d3gwljcq032bb3908\`.qa_session ORDER BY id DESC LIMIT 5;"
```

库名带连字符，**必须用反引号**，否则报 1064。

## 4 为什么前端直连 8101，而不是走网关

网关 `AuthGlobalFilter` 会校验 JWT + Redis 会话，`/api/qa/**` 不在白名单，没有 token 一律 401。
演示的是"页面→后端→库"的写入链路，所以前端代理直指 qa-service。

要连网关（完整链路 `5173 → 8080 → 8101`）需要三件事，属于另一条线：

1. 起 Redis（网关会话校验用）；
2. `AUTH_FIXTURE_ENABLED=true` 启动 auth-service，`POST /api/dev/token?userId=1&role=STUDENT` 拿 token；
3. 前端把 token 存进 `localStorage.yingxin_token`，`VITE_API_TARGET` 改回 `http://localhost:8080`。

## 6 两个坑（都已修，记下来免得再踩）

1. **雪花 ID 到前端会丢精度**：19 位超过 JS 的 `2^53`。`QaSessionVO` 的 `id` / `userId` 已加
   `@JsonSerialize(using = ToStringSerializer.class)`，前端拿到的是字符串。别改回数字。
2. **`el-input-number` 在 `:controls="false"` 下输入不可靠**（实测输入 3003 会拼成 10013003），
   已改用 `el-input` + 正则校验。
