# 本地启动指引

> 适用对象：已按 [环境搭建指南](环境搭建指南.md) 装好 JDK / Node / pnpm / Docker 的成员。本文只讲"怎么把系统跑起来"，不讲安装。
>
> **启动以本文为准，不依赖任何一键脚本。** 脚本必然写死端口与环境假设，而每个人的库在哪、端口被谁占用各不相同，写死反而造成"看起来起了、其实连错库"。本文每一步都给了验证命令，哪一步不过就停在哪一步。

## 0 先定三件事

启动前先明确下面三项，它们决定了第 2、3 步怎么做：

| 项 | 常见选择 | 说明 |
|---|---|---|
| MySQL | 本地 Docker 容器 / 个人云库 | 开发阶段**不共享云库**，谁用哪套库由自己决定 |
| Redis | 本地 Docker 容器 / 独立实例 | 不要写进别人正在用的 Redis（本机禅道自带 Redis 占 6379） |
| RabbitMQ | 本地 Docker 容器 / 不起 | 不起也能跑：埋点发布失败会降级写库，只有 event-worker 空转 |

跨人唯一的契约是**表结构**：表只由 `backend/db/migration/` 的迁移脚本创建，谁也不许手工改库。数据各自灌，见第 5 步。

## 1 前置检查

```bash
java -version          # 需要 17+
node -v                # 需要 20+（管理后台用 Vite 8）
pnpm -v                # 需要 12
docker info            # 不报错 = 引擎可用；报错先启动 Docker Desktop
```

端口占用检查（在起容器**之前**做，这两个端口最常被别的软件占着）：

```powershell
# Windows PowerShell / CMD
netstat -ano | findstr ":3306 " | findstr LISTENING
netstat -ano | findstr ":6379 " | findstr LISTENING
tasklist /fi "PID eq <上一步查到的PID>"      # 看是谁占的
```

```bash
# macOS / WSL / Linux
lsof -i :3306
lsof -i :6379
```

本机已知情况：**禅道自带 MariaDB 占 3306、禅道 Redis 占 6379**。占用了就在第 2 步换端口，不要停掉禅道。

## 2 启动基础设施

### 2.1 全部用本地 Docker（默认）

```bash
cd backend
docker compose up -d
docker compose ps           # 期望 mysql / redis / rabbitmq 三个都是 healthy
```

compose 默认映射 `3306 / 6379 / 5672`。若本机这些端口被占，两种处理：

- 改 `backend/docker-compose.yml` 的 `ports`（例如 `"3307:3306"`），**同时**在第 3 步把同名环境变量设成一样；
- 或者停掉占用者（不推荐停禅道）。

> 两端端口必须一致：库发布在 3307、服务连 3306，会表现为 "Connection refused" 或连到别人的库上。

### 2.2 库/缓存不在本机

只起需要的那部分容器，例如只用本地 Redis 与 MQ、库连自己的云实例：

```bash
cd backend
docker compose up -d redis rabbitmq
```

MySQL 相关的 `MYSQL_*` 环境变量在第 3 步指向云实例即可。云库注意三点：库名带连字符要加反引号、连接需 `MYSQL_SSL_MODE=PREFERRED`（握手失败再改 `REQUIRED`）、出口 IP 要进白名单。

## 3 设置环境变量

`application.yml` 全部是 `${环境变量:本地默认值}`，**改配置不用改代码**。三种写法任选其一（口令含 `%` 时不要用 CMD，CMD 会把它当变量展开吃掉字符）。

PowerShell：

```powershell
$env:MYSQL_HOST="127.0.0.1"; $env:MYSQL_PORT="3307"; $env:MYSQL_DB="yingxin"
$env:MYSQL_USER="yingxin";   $env:MYSQL_PASSWORD="yingxin123"; $env:MYSQL_SSL_MODE="PREFERRED"
$env:REDIS_HOST="127.0.0.1"; $env:REDIS_PORT="6380"
$env:RABBITMQ_HOST="127.0.0.1"; $env:RABBITMQ_PORT="5672"
```

bash / WSL（可存到 `~/.yingxin/db.env` 后 `source`）：

```bash
export MYSQL_HOST=localhost MYSQL_PORT=3307 MYSQL_DB=yingxin
export MYSQL_USER=yingxin MYSQL_PASSWORD=yingxin123 MYSQL_SSL_MODE=PREFERRED
export REDIS_HOST=localhost REDIS_PORT=6380
```

连个人云库时只替换 MYSQL 那组，例如：

```bash
export MYSQL_HOST=<云库域名> MYSQL_PORT=<端口> MYSQL_DB=<库名>
export MYSQL_USER=<账号> MYSQL_PASSWORD='<口令>' MYSQL_SSL_MODE=PREFERRED
```

完整变量清单：`MYSQL_HOST/PORT/DB/USER/PASSWORD/SSL_MODE`、`REDIS_HOST/PORT/PASSWORD/DB`、`RABBITMQ_HOST/PORT`、`JWT_SECRET`、`AUTH_FIXTURE_ENABLED`、`AUTH_INTERNAL_SECRET`、`CORS_ALLOWED_ORIGINS`。

## 4 执行数据库迁移（表结构唯一来源）

```bash
cd backend
./mvnw -Pdb -pl . flyway:migrate          # Windows CMD 用 mvnw.cmd
# 等价：scripts/db-migrate.sh migrate（要求 5 个 MYSQL_* 变量全部已设置）
```

`-pl .` 不能省：profile 只挂在聚合工程上，业务服务不引 Flyway。

验证（期望 **31 行**：30 张业务表 + `flyway_schema_history`）：

```sql
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='yingxin';
SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;
```

**已有结构的库首次接入**必须先基线化，否则会从 `V20261009160001` 重跑并撞 "Table already exists"：

```bash
./mvnw -Pdb -pl . flyway:baseline -Dflyway.baselineVersion=<库里已手工执行的最高版本>
```

常见失败：

| 报错 | 原因 | 处理 |
|---|---|---|
| `Found more than one migration with version ...` | 迁移目录里两个脚本共用版本号 | 按 `V<yyyyMMddHHmm><两位序号>` 改名，保证版本唯一 |
| `Table 'xxx' already exists` | 该脚本曾绕过 Flyway 手工执行 | 结构已齐则按上一段基线化；否则清库重来 |
| `Unknown database` / `Access denied` | `MYSQL_DB` / 账号 / 白名单不对 | 核对第 3 步的变量，云库还要查出口 IP 白名单 |
| 表名大小写不一致 | 数据卷初建时 `lower_case_table_names` 没生效 | 该参数只在卷首次初始化生效，需 `docker compose down -v` 重建 |

## 5 灌入演示数据（可选，仅演示环境）

迁移只建结构，业务数据靠这个脚本；脚本用固定 ID + `INSERT IGNORE`，可重复执行：

```bash
docker exec -i yingxin-mysql mysql -uyingxin -pyingxin123 yingxin < backend/scripts/seed-demo-data.sql
# 你的容器名/账号不一致时按实际替换；库在云上则用 mysql 客户端连过去执行
```

灌入内容（当前版本）：1 个管理员、40 名学生、40 条身份、140 条报到进度、259 条埋点、12 条问答、119 条提问日志。

灌完让看板缓存立即失效：

```bash
docker exec yingxin-redis redis-cli INCR yx:admin:dash:version
```

> **正式环境不要执行 seed**：脚本是演示数据，含固定账号与假数据。
> 注意：RBAC 的模块/权限点/用户组属于**字典数据，在建表迁移里**（`V20261119120001__auth_rbac.sql`），不需要额外灌。

## 6 启动后端服务

先构建（首次或改了代码后）：

```bash
cd backend
./mvnw clean install -DskipTests
```

再按需启动。**网关 + 本次要演示的服务**，每个服务一个终端：

```bash
./mvnw -pl services/gateway  spring-boot:run
./mvnw -pl services/auth-service spring-boot:run
./mvnw -pl services/qa-service spring-boot:run
./mvnw -pl services/checkin-service spring-boot:run
./mvnw -pl services/admin-service spring-boot:run
./mvnw -pl services/event-worker spring-boot:run
```

也可以用构建好的 jar（启动更快，环境变量同样生效）：

```bash
java -jar services/gateway/target/gateway-1.0.0-SNAPSHOT.jar
```

| 服务 | 端口 | 有业务代码？ |
|---|---|---|
| gateway | 8080 | 路由 + 鉴权 |
| auth-service | 8100 | 登录、会话、RBAC |
| qa-service | 8101 | 问答、未解答 |
| checkin-service | 8102 | 报到步骤、打卡、凭证 |
| navigation-service | 8103 | 仅 ping（骨架） |
| aid-service | 8104 | 仅 ping（骨架） |
| life-service | 8105 | 仅 ping（骨架） |
| content-service | 8106 | 仅 ping + 文件接口 |
| admin-service | 8107 | 管理员登录、看板 |
| event-worker | 8110 | 无 Web 端口，RabbitMQ 消费端 |

逐个验证（经网关，路径不裁剪前缀）：

```bash
curl http://localhost:8080/api/auth/ping
curl http://localhost:8080/api/qa/ping
curl http://localhost:8080/api/checkin/ping
curl http://localhost:8080/api/admin/ping
curl http://localhost:8080/actuator/health     # 网关健康
```

event-worker 没有 HTTP 端口，看它窗口日志出现 `Started EventWorkerApplication` 即正常。

## 7 启动前端

两个工程相互独立，各自装依赖：

```bash
cd frontend/admin-web && pnpm install && pnpm dev      # http://localhost:5173，/api 已代理到 8080
cd frontend/miniprogram && pnpm install && pnpm dev:h5  # 学生端网页（H5），小程序端已裁剪
```

版本约束（已钉死，不要统一升级）：后台 Vite 8；学生端 Vite 必须 `5.2.8`，`@dcloudio/*` 用同一批次号。

## 8 端到端自检（5 条）

1. 打开 <http://localhost:5173/login>，验证码图片能出。
2. `admin` / `123456` + 验证码 → 进入看板（会话是 HttpOnly Cookie，2 小时过期）。
3. 看板 5 个指标非 0：报到 40/40、提问数、缓存命中率、平均耗时、未解答。
4. 越权被拒：用学生令牌打管理端应得 403 —— 走 `/api/auth/login`（`loginType=1`，`ST2026001`/`123456`）拿 token，再带 `Authorization: Bearer` 请求 `/api/qa/admin/questions`。
5. 打过卡或提过问后，看板数字在 5 秒内自己变化（版本号失效机制）。

## 9 停止与清理

```bash
cd backend
docker compose stop            # 停容器、保数据
docker compose down            # 停并删容器、保数据卷
docker compose down -v         # 连数据卷一起删 —— 库会被清空，慎用
```

服务窗口直接 `Ctrl+C`。旧 Cookie 在会话过期或登出前仍有效，排查登录问题时可先清浏览器 Cookie 再看。

## 10 排错速查

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 服务起来但所有接口 500 / 连接拒绝 | 服务连的端口 ≠ 容器发布的端口 | 核对第 3 步变量与 `docker compose ps` 的映射 |
| 连上了但表不存在 | `MYSQL_DB` 写错（云库的库名是环境 ID，不是 `yingxin`） | 改成实际库名 |
| 登录一直提示账号或密码错误 | 库是空的、没灌 seed | 执行第 5 步 |
| 登录成功但页面马上跳回登录页 | Cookie 没带上 / 会话已过期 | 确认前端走 5173 代理、服务端 Redis 与网关是同一个 |
| 看板全 0 | 没有埋点数据，或 Redis 里快照版本没失效 | 灌 seed 后 `INCR yx:admin:dash:version` |
| 前端请求 404 且 `{"code":9001}` | 路径不存在 | 网关前缀是 `/api/<服务>/...`，没有 `/v1` |
| RabbitMQ 连不上导致服务日志刷错 | 没起 MQ | 起 `rabbitmq` 容器；或忽略（仅 event-worker 受影响） |
